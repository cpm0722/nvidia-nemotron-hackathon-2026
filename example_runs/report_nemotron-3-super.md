# Nemotron 3 Super

## Executive Summary
NVIDIA Nemotron 3 Super is a 120B‑parameter LatentMixture‑of‑Experts language model with 12B active parameters, designed for agentic workflows, long‑context reasoning, and high‑volume workloads such as IT ticket automation[^1][^2]. Official benchmarks show strong performance on reasoning and coding tasks, including an MMLU‑Pro score of 83.73 and a GPQA (no tools) score of 79.23[^1][^2]. Community discussions highlight both enthusiasm for its reasoning capabilities and concerns about deployment practicalities, such as inference speed on VLLM versus alternative backends[^3][^4]. Some users report tool‑call parsing errors and hardware compatibility issues with FP8/NVFP4 quantizations on older GPUs[^5][^6]. Overall, the model delivers cutting‑edge accuracy but requires careful consideration of serving infrastructure and quantization choices.

## Official Performance
According to Artificial Analysis, Nemotron 3 Super achieves an Intelligence Index of 35.97, a Coding Index of 31.19, and an Agentic Index of 40.18, with notable results on GPQA Diamond (80.0%) and TAU‑2 (67.8%)[^1]. The model card reports MMLU‑Pro at 83.73, HMMT Feb25 (with tools) at 94.73, and GPQA (no tools) at 79.23, alongside strong LiveCodeBench scores of 78.69 (v6) and 81.19 (v5)[^2]. Additional metrics include SciCode (subtask) 42.05, HLE (no tools) 18.26, and Terminal Bench (hard subset) 25.78[^2]. The model supports up to 1M token context length and is licensed under the NVIDIA Nemotron Open Model License for commercial use[^2]. Compared to prior Nemotron 3 variants, the Super version adds Multi‑Token Prediction layers and NVFP4 quantization to improve throughput and quality[^2]. While these benchmarks place it among the top open models, absolute rankings vary across leaderboards, and some community members note that real‑world throughput can diverge from synthetic scores depending on the serving stack[^3].

## Community Reactions
Reddit users discuss the practical performance of Nemotron 3 Super when deployed with different inference engines, noting that VLLM implementations often yield lower tokens‑per‑second than llama.cpp‑based setups; one user reported ~15 t/s with the Nano NVFP4 variant in VLLM versus ~30 t/s using Unsloth’s MXFP4 version in LM Studio[^3]. Another thread highlights the long‑context strength of the model, describing successful ingestion of large markdown files but warning that prompt processing remains hardware‑bound and can take several minutes per document without faster compute[^4]. Conversations also mention the model’s multi‑token prediction capability as a way to narrow the gap between VLLM and llama.cpp inference speeds when properly configured[^3]. Despite the lack of activity on ArcaLive, GeekNews, and Lobsters in the collected evidence, the Reddit discourse reflects both excitement about the model’s reasoning and agentic features and frustration over deployment complexity and hardware requirements[^3][^4]. Users further point out that documentation sometimes overstates GPU compatibility, citing FP8/NVFP4 quantizations that require Hopper‑class (CC 89+) GPUs rather than the advertised A100 support[^5][^6]. Overall, community sentiment is cautiously optimistic, praising the model’s capabilities while urging potential adopters to benchmark their specific serving environment before committing to production workloads.

## Key Takeaways
- Validate the model’s throughput on your chosen serving stack (VLLM, SGLang, or TRT‑LLM) before assuming peak benchmark scores translate to real‑world latency.  
- Confirm GPU compatibility for FP8/NVFP4 quantizations; these require Hopper‑or‑later (CC 89+) devices, not older Ampere cards like the A100.  
- Leverage the model’s 1M‑token context and Multi‑Token Prediction for agentic workflows such as IT ticket automation or long‑context RAG, where reasoning depth matters more than raw speed.  
- Watch for tool‑call XML parsing issues in multi‑turn reasoning; consider applying the proposed chat_template.jinja patch or disabling reasoning until a fix is upstream.  
- Monitor community patches and documentation updates, as active discussions on HuggingFace indicate ongoing improvements to reasoning_effort handling and hardware compatibility notes.  
- If deploying on Blackwell GPUs, enable expert parallelism and tensor parallelism as recommended in the model’s quick‑start guides to maximize throughput.  
- For multilingual applications, note that the model supports English, French, German, Italian, Japanese, Spanish, and Chinese, but benchmark scores for non‑English variants are lower than the English‑only MMLU‑Pro.  

## Points of Contention
- **Topic:** GPU compatibility for FP8/NVFP4 quantization  
  - **Official / Claim A:** The model card lists the minimum GPU requirement as “2× H100-80GB” for the FP8/NVFP4 version, suggesting compatibility with H100 (Hopper) GPUs[^2].  
  - **Community / Claim B:** Users report that attempting to run FP8/NVFP4 quantizations on an A100 (CC 80) fails with an error stating CC 89+ is required, indicating the quantizations need Hopper‑class hardware[^5][^6].  
  - **Perspective:** While the base model may run on H100s, the specific FP8/NVFP4 quantizations distributed via HuggingFace are not functional on Ampere GPUs; users should verify their GPU architecture before selecting these quantizations.  

- **Topic:** Tool‑call XML label hallucination in multi‑turn reasoning  
  - **Official / Claim A:** Official documentation highlights strong agentic and tool‑use capabilities, citing LiveCodeBench and TauBench scores as evidence of reliable tool interaction[^2].  
  - **Community / Claim B:** A HuggingFace discussion shows the model frequently outputs malformed `<function=parameter=code>` tags instead of the expected nested XML, breaking standard parsers and causing execution failures in automated pipelines[^7].  
  - **Perspective:** The issue appears in the default chat template; applying the community‑suggested patch that maps OpenAI’s `reasoning_effort` to the template’s `low_effort` and `enable_thinking` flags resolves the hallucination, or users can disable reasoning until the fix is merged.
